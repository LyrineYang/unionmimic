## 并行资源应解决什么问题

- 多个独立训练进程可以缩短配置筛选时间，但不会自动得到一个多技能策略。
- 同一策略的多环境采样可增加不同接触、失败、扰动经验；单物体上的有效增益尚待学习曲线验证。已有512环境短测提高样本吞吐约6.6倍，同时减少约18%的actor更新/小时，不能据此宣布学习加速。
- 优先让同一物体的不同动作/轨迹承担新增环境，各动作共享物理模型与目标条件策略。目标改为每GPU小时新增通过的任务/轨迹、最差动作表现与未见轨迹成功率；多物体不作为这项验证的前提。
- 外部逐任务评估可以并行；冻结策略后独立回合可分片，但须固定每任务回合数、随机种子、归一化和汇总权重。
- 24GiB是容量目标，实际配置服从有效采样与外部评测收益。多物体接触、资产、相机和轨迹缓存会改变容量，原单物体估算不能直接沿用。

## 核实 SuperMimic 的比较口径

作者报告使用264.56小时BONES-SEED；129,514是过滤后的运动片段数，不是动作向量数或技能类别数。SONIC/SM的失败数分别为179、25（1 H100×3小时）、0（2 H100×9.8小时）。这些片段是两方法的训练动作，因此检验训练库覆盖，不证明未见动作泛化。逐片段从首帧运行，采用统一终止，关闭域随机化/观测噪声；总训练计时包括采集、模型与策略更新，不含之后的checkpoint评估。来源：[官方说明](https://supermimic.github.io/)。

## 对当前Sharpa实现的具体缺口

本地源码：`unionmimic/online/simulator.py:35`固定`singleObject=set_obj6_block_corner`、`axis=z`，并断言单物体；上游已有`set_z/set_y/set_x4`资产配置，但并未进入当前SM训练。

`unionmimic/online/task.py:20`的F输入有物理状态、质量/摩擦/PD等上下文，没有物体几何描述。不同形状在相似状态下可产生不同接触，直接混入多物体会增加模型歧义；需要几何/接触表征及按物体诊断，不能仅增加object ID后宣称未见物体泛化。

actor当前是四帧本体/触觉/轴指令，没有时变物体目标轨迹。真正多动作需要目标编码、轨迹相位、长度与终止、按轨迹采样和逐轨迹评估。预先给定的未来目标轨迹属于合法命令；未来真实执行状态、触觉或深度不能用于想象纠错。

Sharpa当前手掌固定。公开HOI轨迹通常包含手腕平移/旋转；先做可达性与接触检查。只把全球运动减去手腕位姿并不能保证在固定手掌和原重力下仍物理可行。更换手/增加手臂后，WSM的观测、动作与权重兼容性也须重新验证。

## 单物体动作的具体设计与实现风险

| 动作层次 | 初始候选 | 观察结果 |
| --- | --- | --- |
| 方向与速度 | 正反向、两档目标角速度；数值由现有可达速度和短试跑固定 | 方向正确率、速度跟踪误差、滑落与接触切换 |
| 到位与保持 | 相对初态转90°/180°后保持；角度为候选，需先验证可达性 | 到位率、过冲、保持漂移、稳定时间 |
| 连续序列 | 旋转→减速→保持→反转，以及未见顺序/时长组合 | 完整序列成功、切换阶段失败、跨动作负迁移 |
| 外部参考 | 单物体公开HOI中的可达操作片段；保留原轨迹身份 | 原判定下逐轨迹成功与误差；明确适配差异 |

以上均是待实现候选，同一手/物体/控制器可复用物理学习，但接触分布改变仍需验证F误差和策略梯度有效性。x/y轴、重抓或平移后置，不假定当前初始抓姿都可达。

源码审查发现当前`HandTask.reward`对转速低于阈值累计stall并判失败，且奖励鼓励持续旋转而非目标速度/姿态。保持任务必须使用独立版本的目标条件奖励和终止规则：仅在命令要求保持的阶段停用“必须转动”的判定，保留掉落等物理失败。不能修改原持续旋转任务来提高旧得分。

当前actor没有直接物体姿态估计，角度保持的可观测性须明确：采用部署可得的视觉/历史估计则SM与SM+WSM共享相同可用传感输入；若采用仿真真值作诊断，单列oracle组，不混入部署结论。不得只给先验组额外物体真值。WSM输入契约改变时重新验证权重兼容性。

目标序列按真实控制时间推进，在想象每一步计算对应g；允许预先给定未来目标，禁止真实未来传感状态纠错。回放保存trajectory_id、phase、目标与episode边界；物理F复用，任务依赖的奖励/失败和critic不可忽略目标。新网络接口或任务定义不兼容旧checkpoint时拒绝静默加载；从头学习比较不混用旧actor热启动。

## 外部评测合同

1. 固定版本、物体/轨迹清单、手型、控制频率、初态、终止与噪声；严格记录是否使用参考动作残差、专家示范、真实物体状态或已知几何。允许的信息分别列于actor、critic、F。
2. 原生benchmark复验与Sharpa移植版分表。更换手型、删减轨迹、固定手腕或改成功阈值后，须标注adapted/subset，不能引用原论文分数作同协议排名。
3. 用训练分区内的开发集选择checkpoint/参数；最终测试冻结模型、归一化与WSM适配。失效/不可达数据预先按规则过滤并报告数量，不能依据某方法失败事后删除。
4. 主报告为完整轨迹成功/失败、按物体/技能的宏平均、最差组、完成度及物体位姿误差；失败轨迹仍计入分母。成功轨迹精度单列，不能幸存者筛选代替全部结果。
5. 分别报告训练库覆盖、未见轨迹、未见物体。语义相近的生成变体可能跨轨迹split；忠实复现原split之外，增加按源示范/物体分组的严格测试，不能混称更强泛化。
6. 达到同一外部成功水平所需墙钟/GPU小时包含采样、模型、策略、参考预处理、先验/教师训练或采用发布权重的摊销说明；评估成本单列。GPU型号与信息权限不同则不直接声称论文加速比。
