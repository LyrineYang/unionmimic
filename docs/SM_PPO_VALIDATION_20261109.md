## 如何判断SM是否更快

**先看同等控制质量，再比较时间。** 不只比较奖励，也不挑一段成功视频。

1. 同时报告旋转进度、失败率和轴偏差，奖励作为辅助。预先约定达到某一策略的效果需要这些指标共同满足标准；不接受更大旋转伴随明显更多掉落。
2. 本次探索性查询点为PPO在30/60/90分钟与末次检查点的表现；找SM时间序列中满足对应旋转、失败和偏轴条件的最早已测检查点。未找到就报告未达到，不改变查询点或放宽标准来制造优势。
3. 开发评估只用于定位候选。正式确认锁定候选和误差容忍度后，在共同未用于调参的仿真种子上各评估512个首回合；如需声称统计稳定，再补独立训练种子。当前两小时试验只提供单种子探索结论。
4. 时间同时列总墙钟、开发评估时间、扣除评估的学习时间、GPU小时和有效仿真转移数。SM必须包括300轮模型预热、采样和F训练。两算法评估频率不同，不能只用受监控开销影响的总墙钟宣称算法加速。
5. 两小时PPO预算结束仍未达标，只能说“该预算内未达到”；不能外推PPO需要多少小时。离线评估旧SM的GPU成本单列，也不能把它算进旧checkpoint的训练时间。

SM的物理模型训练需要模拟器状态；部署actor没有读入这些特权量。PPO使用相同actor观测和critic特权量。PPO网络为匹配SM而调整，属于受控方法比较，不冒充PPO原生默认网络逐项复现。

本轮不会预先承诺SM优于PPO。若PPO更快或两者各有优势，按实测报告，再决定是否值得做更大范围的成本实验。

## 11月10日一小时动作与速度对照

本轮以同一角块的 +z 为已知能力阳性对照，−z 为新动作。两个方向各跑一条 SM 与 PPO，占用四张同型号 V100。每卡从零开始，独立 60 分钟硬预算，包含启动、采样、模型预热及评估。首次比较固定同一个训练种子，15、30分钟和末次检查点按同一开发协议评估。保留相同的 actor／critic 初始化哈希、64 步初始采样、环境、目标轴、动作接口、奖励、终止、随机化、512 个首回合及留出种子。按方向单独报告有符号旋转、失败率和轴偏差。

PPO 共享环境与归一化的初始采样，之后即按原配方进行 on-policy 更新。SM 的 F 预热计入 SM 自己的端到端时间，PPO 无需空等。另一张表可单列首次 actor 更新后的用时，便于区分启动成本与学习进度。调试检查点只用于验证执行，正式试跑重新初始化。若后续使用已有 actor 转移动作，应单独报告两组相同权重起点、原始训练成本和新增一小时成本。

纠正吞吐口径。此前约 3.5 倍是 Sharpa 实测的 PPO/SM 流水线推进比。若相近旋转量仍需要约 2.8 倍的真实样本差，按当前 PPO 吞吐反推，SM 的稳态打平点约为 1,490 条真实转移/秒，较历史 1,190 条/秒高约 25%。这只是固定样本效率和稳态吞吐下的估算，端到端比较还要包含预热与评估，且相近旋转量并未配平失败率和轴偏差。

本轮先验证两项工程改动。8 步角块物理拟合只执行所需动力学路径，传感和终止监督仍在原单步损失，完整想象仍使用传感和终止头。模型和 critic 的有限值检查合并 GPU 标量回传，保留逐优化步检查。固定输入的 8 步物理状态、损失梯度和终止输入已通过 CPU 对照。另将一小时实验的 F 专训由 300 轮试缩至 60 轮，标记为新配方；正式参考配方保持 300 轮。一小时结果衡量这组改动后的端到端表现，60 轮本身的净效果需另做消融。[预热参考 LEAP yaw](https://github.com/Msornerrrr/in-hand-rotation-mjlab/blob/0ab03eb2244b4a1a020d94ef38a4823bb9e15ba0/scripts/wm/train_yaw.py#L52) · [LAFAN1 复现训练循环](https://github.com/dhmbb2/supermimic_vibe/blob/d0934d069207ee745be8489d9631a8314c94c1f3/code/supermimic/train.py#L449)。

一小时开发门槛在本轮新结果出炉前固定为每回合平均目标方向旋转 ≥25 rad、失败率 ≤10%、平均轴偏差 ≤0.35 rad。候选达到开发门槛后，用锁定种子重新核验三项；后续多种子才能支持训练速度结论。若 +z 通过、−z 未通过，优先检查反向有效交互、动作到奖励的梯度方向和回放覆盖。两者均未通过时，先看采样／拟合／actor-critic 分项时间，再核对 F 提前进入策略更新后的预测与失败覆盖。
