## 如何判断SM是否更快

**先看同等控制质量，再比较时间。** 不只比较奖励，也不挑一段成功视频。

1. 同时报告旋转进度、失败率和轴偏差，奖励作为辅助。预先约定达到某一策略的效果需要这些指标共同满足标准；不接受更大旋转伴随明显更多掉落。
2. 本次探索性查询点为PPO在30/60/90分钟与末次检查点的表现；找SM时间序列中满足对应旋转、失败和偏轴条件的最早已测检查点。未找到就报告未达到，不改变查询点或放宽标准来制造优势。
3. 开发评估只用于定位候选。正式确认锁定候选和误差容忍度后，在共同未用于调参的仿真种子上各评估512个首回合；如需声称统计稳定，再补独立训练种子。当前两小时试验只提供单种子探索结论。
4. 时间同时列总墙钟、开发评估时间、扣除评估的学习时间、GPU小时和有效仿真转移数。SM必须包括300轮模型预热、采样和F训练。两算法评估频率不同，不能只用受监控开销影响的总墙钟宣称算法加速。
5. 两小时PPO预算结束仍未达标，只能说“该预算内未达到”；不能外推PPO需要多少小时。离线评估旧SM的GPU成本单列，也不能把它算进旧checkpoint的训练时间。

SM的物理模型训练需要模拟器状态；部署actor没有读入这些特权量。PPO使用相同actor观测和critic特权量。PPO网络为匹配SM而调整，属于受控方法比较，不冒充PPO原生默认网络逐项复现。

本轮不会预先承诺SM优于PPO。若PPO更快或两者各有优势，按实测报告，再决定是否值得做更大范围的成本实验。
